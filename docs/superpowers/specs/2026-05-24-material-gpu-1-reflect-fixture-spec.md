C++/GLSL mirror drift is caught at build time, before a runtime slice ever
touches it. No game code changes. No runtime behavior changes.

## 3. Fixture shader

**Path:** `shaders/fixtures/material_gpu_contract.frag`

A minimal, non-runtime fragment shader whose sole purpose is to produce
a spirv-cross `--reflect` golden. It is never compiled into `mc2.exe`.

### Design constraints

- `#include <include/material_gpu.hglsl>` — exercises the actual include path
- `layout(std430, binding=5) readonly buffer MaterialTable { MaterialGpu materials[]; }` — binding 5 matches the reservation in `tools/material_cook/reflect_expected_layout.md`
- `main()` reads all 8 struct fields in a single expression — required so spirv-cross does not optimize the struct away before reflection
- Single `layout(location=0) out vec4 o_color` output — minimum valid fragment shader
- No `#version` directive (prepended by `makeProgram()` convention; reflect.py uses default `#version 430`)
- No conditional compilation (`#ifdef` guards) — one variant suffices

### Why all 8 fields must be read

spirv-cross reflects only live resources. If a field is never accessed in
reachable code, the compiler may eliminate it from the SPIR-V binary before
spirv-cross sees it. The `main()` body uses a single accumulated float
expression touching all 8 fields — this is not game logic, it is a reflection
keep-alive.

## 5. REQUIRED_INVARIANTS entries

Eight `type_member` checks against the `MaterialGpu` named type in the
spirv-cross raw JSON. These lock field offsets independently of the golden
and survive `--update`.

| Field                 | offset | C++ static_assert ref                        |
|-----------------------|--------|----------------------------------------------|
| `albedoTex`           |  0     | `offsetof(MaterialGpu, albedoTex) == 0`      |
| `normalTex`           |  4     | `offsetof(MaterialGpu, normalTex) == 4`      |
| `metallicRoughnessTex`|  8     | `offsetof(MaterialGpu, metallicRoughnessTex) == 8` |
| `emissiveTex`         | 12     | `offsetof(MaterialGpu, emissiveTex) == 12`   |
| `flags`               | 16     | `offsetof(MaterialGpu, flags) == 16`         |
| `baseColorFactor`     | 20     | `offsetof(MaterialGpu, baseColorFactor) == 20` |
| `metallicFactor`      | 24     | `offsetof(MaterialGpu, metallicFactor) == 24`|
| `roughnessFactor`     | 28     | `offsetof(MaterialGpu, roughnessFactor) == 28` |

### Why `type_member` rather than `ssbo_member`

`ssbo_member` checks the top-level SSBO block member (the `materials[]` array
itself). `type_member` checks the nested struct's fields by scanning
`raw["types"]` for the named type `MaterialGpu`. This is the correct check
for struct layout — the same pattern already used for `PerDrawEntry.objectIdRaw`
at `reflect.py:139-151`.

### `array_stride` protection

`array_stride = 32` is captured in the golden file (the normalized `ssbos[]`
entry for `MaterialTable`). Golden comparison catches stride drift. An explicit
`ssbo_member` array_stride invariant is not added — the golden is sufficient
for this field, and adding a new invariant check type would exceed the slice's
scope.

## 8. Invariant summary (what CI now enforces)

After this slice ships, the following are hard build-gate violations:

| What drifts | How caught |
|---|---|
| Any `MaterialGpu` field renamed or reordered | `check-material-gpu-mirror.sh` (field order) + 8 `type_member` invariants (offsets) |
| Struct grows past 32 bytes | `static_assert(sizeof == 32)` in C++ |
| GLSL mirror diverges from C++ field order | `check-material-gpu-mirror.sh` |
| Golden diverges from reflection | `reflect.py` golden comparison |
| Binding 5 changes | golden comparison |
