## Coordination: LOD-handoff and GPU-tree safety

**LOD-handoff (in-flight fix):** The active LOD-handoff fix has three paths. Path 1 reintroduces `TransformMultiShape` for offloaded actors as a texture-handle side effect. If Path 1 lands before Stage 3.B, it puts per-frame CPU work inside the block slice 3 skips. **Preferred:** ship Stage 3.B before the LOD-handoff fix, or require LOD-handoff to use Path 2 or Path 3 (pure-GPU, no CPU re-entry). If Path 1 ships first, add `!g_useGpuObjects` to the call-site composition as a temporary guard and document it. See `memory/mc2_texture_handle_is_live.md`.

**CPU path staleness gate — CRITICAL (adversarial review C1):** `TG_Shape::Render()` at `mclib/tgl.cpp:2876` contains a staleness guard: it returns immediately if `lastTurnTransformed != turn`. `lastTurnTransformed` is set to `turn` inside `TransformMultiShape`. If `update()` is skipped, `TransformMultiShape` does not run, `lastTurnTransformed` stays at the prior frame's `turn`, and the guard fires — **the tree disappears on the CPU/legacy rendering path.** `g_useGpuStaticProps` defaults to `false` (killswitch default per `gos_static_prop_killswitch.h`). With GPU off and skip env set, ALL trees vanish on skipped frames.

**The skip gate must include a GPU-path guard.** At the call site in Task B.3:
```cpp
const bool gpuPath = g_useGpuObjects || g_useGpuStaticProps;
if (s_staticUpdateSkip && gpuPath && appearanceClaimsStatic && !ownerForcesDynamic)
```
This restricts the skip to sessions where the GPU path is providing vertex data, which is the only path where skipping `TransformMultiShape` is safe.

**GPU-eligible trees (secondary concern):** `TreeAppearance::update` at `bdactor.cpp:4382` also runs `CacheGpuLightData` + `TransformMultiShape_PositionsOnly` for GPU-eligible in-view trees. For truly static trees, world-space positions are invariant and MC2 has no dynamic time-of-day, so the GPU data cache is also invariant. This is safe given the `gpuPath` guard above ensures the GPU path is active. The visual canary in Task B.4 Step 4 is the empirical backstop for any lighting staleness.

**Backface culling and palm trees:** `TransformMultiShape` uses camera position (`msl.cpp:1367/1691`) to compute `backFacePoint` (camera in shape space) for per-face visibility. For primary trees (two static X-crossed planes), staleness risk depends on camera angle:
- At **90° elevation** (looking straight down): face normals are nearly perpendicular to camera ray, minimal backface flipping on lateral pan.
- At **15° elevation** (near-horizontal, supported by the MC2 camera system): face normals are close to parallel with camera ray. Lateral pan or azimuthal movement at this angle causes visible backface state changes — a stale `backFacePoint` would render the wrong face of each plane.

The camera system supports 15°–90° elevation and azimuthal movement (full 3D camera). **Backface culling staleness is therefore a real risk at low elevation angles.** Palm tree billboards additionally need per-frame camera-facing updates at any elevation angle.

The visual canary in Task B.4 Step 4 MUST test at minimum elevation (~15°) AND with azimuthal movement. If backface artifacts are visible on primary trees at any tested angle, `TreeAppearance::IsStaticNow()` should return `false` (abort tree optimization; fall back to Stage 3.C's walls/bridges which have no camera-dependent faces). Palm tree artifacts are similarly a blocker for default-on flip.

**Why `!needsFullBakeNextFrame` (CRITICAL-1 fix):** `TreeAppearance` has no appearance-internal animation dynamism. However, the GPU batcher uses `needsFullBakeNextFrame` (declared at `bdactor.h:480`) as a per-actor recovery signal: `render()` sets it when the actor's shape was not submitted to the GPU batcher this frame (late-registration, unregistered shape node). `update()` reads it to force a full `TransformMultiShape` next frame and clears it. Skipping `update()` when `needsFullBakeNextFrame=true` breaks this recovery loop — the tree stays in an unsubmitted state permanently. Returning `!needsFullBakeNextFrame` keeps recovery frames dynamic; once submission succeeds, the flag clears and subsequent frames skip correctly.

The renderer-session guard (`gpuPath`) in Task B.3 is belt-and-suspenders: if both GPU paths are off, `needsFullBakeNextFrame` should remain `true` (GPU never submits), so `IsStaticNow()` returns `false` and the gate is already inert. The `gpuPath` guard provides a hard short-circuit for the initial frame before `render()` has been called.

The only other dynamism is `OBJECT_FLAG_FALLING` on the owning `TerrainObject`, set externally by collision callbacks at `terrobj.cpp:352-353` and `bldng.cpp:1453-1455`. The call site handles this (Task B.3). The appearance has no back-pointer.

**Palm tree note:** Rare palm tree billboards use the same `TreeAppearance` class. Skipping `update()` for palm trees locks their camera-facing rotation.
